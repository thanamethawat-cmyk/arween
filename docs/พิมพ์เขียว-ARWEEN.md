## 1. ภาพรวมผลิตภัณฑ์

**ชื่อเต็ม:** ARWEEN: Superior Operations Management Cycle  
**ชื่อภาษาไทยตามข้อเสนอ:** เอ อาร์ วีน วงจรการบริหารงานที่เหนือกว่า

**หลักการสำคัญ:** การทำดีอย่างมีคุณภาพ ต้องได้รับผลตอบแทนที่เหนือกว่า

**ARWEEN คืออะไร**  
ระบบช่วยองค์กรบันทึกงานในโปรเจกต์ ให้ระบบช่วยวิเคราะห์และให้คะแนนอย่างโปร่งใส พร้อมเหตุผลที่ย้อนดูได้ เพื่อให้งานเบื้องหลังถูกมองเห็น และนำไปใช้ประกอบการให้รางวัลอย่างเป็นธรรม

**ปัญหาที่ต้องการแก้**

1. การประเมินผลงานไม่โปร่งใส หัวหน้ามักประเมินจากความทรงจำหรือรายงานท้ายปี
2. คนที่ทำงานเบื้องหลัง (ปิดทองหลังพระ) ไม่ถูกบันทึกผลงาน
3. ระบบทำงานประจำวัน กับระบบบุคคล (HR) แยกกัน
4. ความทุ่มเทไม่สอดคล้องกับผลตอบแทน ทำให้หมดไฟและลาออก

**ใครใช้**

| กลุ่ม | ใช้ทำอะไร |
|-------|-----------|
| พนักงาน | บันทึกงานในโปรเจกต์ ดูคะแนนและเหตุผล |
| หัวหน้าโปรเจกต์ | ดูความคืบหน้า ยืนยันคะแนน สรุปทีม |
| ผู้บริหาร / ฝ่ายบุคคล | ใช้ข้อมูลประกอบการพิจารณาโบนัสหรือเลื่อนตำแหน่ง |

รูปแบบธุรกิจ: ขายให้องค์กร (B2B) โดยเฉพาะบริษัทขนาดกลางถึงใหญ่ และองค์กรที่ทำงานเป็นโปรเจกต์

## 2. คำสำคัญ (จากข้อเสนอ + คำอธิบายง่าย ๆ)

| คำ | ความหมายภาษาไทยง่าย ๆ |
|----|------------------------|
| Invisible AI Observer | ผู้ช่วยปัญญาประดิษฐ์ที่ทำงานเบื้องหลัง ช่วยดูและให้คะแนนงานโดยไม่บังคับให้พนักงานเขียนรายงานแยก |
| High Impact Action | งานที่มีผลต่อโปรเจกต์สูง เช่น แก้ปัญหาซับซ้อน หรือช่วยทีมข้ามแผนก |
| Merit-to-Earn | การเปลี่ยนคะแนนความทุ่มเทเป็นผลตอบแทน เช่น โบนัสหรือวันหยุด — เวอร์ชันต้นแบบยังไม่จ่ายเงินอัตโนมัติ |
| Audit Trail | ประวัติการให้คะแนนที่ย้อนดูได้ รู้ว่าคะแนนมาจากงานไหนและเหตุผลอะไร |
| Multi-Agent | การแบ่งงานให้ระบบ AI หลายส่วนช่วยกัน เช่น เทียบงานกับเป้าหมาย ให้คะแนน สรุปสัดส่วน ตรวจพฤติกรรมผิดปกติ |
| Anchor Framework | ตัวตั้งหลักของการประเมิน: วัตถุประสงค์ (Objectives), เป้าหมายงานส่งมอบ (Milestones), ตัวชี้วัด (KPIs) |
| Impact Score | คะแนนผลกระทบ 0–10 ที่ผูกกับ Milestone / KPI ไม่ใช่จากจำนวนข้อความ |
| Contribution Ratio | สัดส่วนผลงานรายบุคคลที่รวมกันครบ 100% ใช้ประกอบ Merit-to-Earn |
| Dispute | การยื่นโต้แย้งคะแนน เมื่อพนักงานไม่เห็นด้วย |

## 3. เกณฑ์เปอร์เซ็นต์การทำงาน (ล็อกแล้ว)

**หลักการ:** ประเมินจากผลลัพธ์ที่มีคุณค่า ไม่ใช่จากปริมาณกิจกรรม (Outcome-driven over Activity-driven)

**ตัวตั้งหลัก:** วัตถุประสงค์ · เป้าหมายงานส่งมอบ · ตัวชี้วัดความสำเร็จของโครงการ  
บันทึกงานรายวันและการแชทแก้ปัญหาในพื้นที่โปรเจกต์ส่วนรวม = **หลักฐาน (Evidence)** เพื่อพิสูจน์ว่างานนั้นช่วยเป้าหมายใด ไม่ใช่ตัวตั้งคะแนนโดยตรง

### สองมิติที่ต้องแยกกันชัด

| มิติ | ช่วงค่า | ความหมายสั้น ๆ |
|------|---------|----------------|
| ความคืบหน้าโครงการรวม (Project Progress) | 0–100% | น้ำหนักตามแผนงาน — เมื่อ Deliverable / KPI สำเร็จ หลอดความคืบหน้าขยับตามน้ำหนักจริง |
| สัดส่วนผลงานรายบุคคล (Contribution Ratio) | รวมกันครบ 100% | จาก Impact Score 0–10 ของแต่ละคนต่อ Milestone / KPI แล้วแปลงเป็นสัดส่วน |

### Multi-Agent ที่ใช้กับเกณฑ์นี้

| Agent | งาน |
|-------|-----|
| Agent 1 — Context Analyzer & Milestone Mapper | เทียบบันทึกงานกับตารางเป้าหมาย/KPIs ให้ Impact Score + เหตุผล |
| Agent 2 — Contribution Calculator | แปลง Impact Score เป็นสัดส่วนรวม 100% |
| Agent 3 — Fraud & Bias Detector | ระงับกิจกรรมซ้ำที่ไม่มีผลต่อตัวชี้วัด (Anti-Gaming) |

รายละเอียดเต็ม: [เกณฑ์เปอร์เซ็นต์การทำงาน.md](./เกณฑ์เปอร์เซ็นต์การทำงาน.md)

## 4. วงจรทำงาน 4 หน้าที่ของทีม AI

ระบบ AI ใน ARWEEN ทำได้เฉพาะสี่งานนี้ ตามลำดับ

```
งานเกิดในพื้นที่โปรเจกต์ส่วนรวม
        ↓
1. รวบรวมข้อมูล — เก็บว่าใครทำอะไร เมื่อไหร่
        ↓
2. แจ้งเตือน — สรุปรายสัปดาห์ / สัญญาณปั่นคะแนน / ข้อโต้แย้งค้าง
        ↓
3. อำนวยความสะดวก — รวมสถานะงานและเอกสารไว้ที่เดียว
        ↓
4. ประเมินแบบเป็นกลาง — ให้คะแนนพร้อมเหตุผล และสรุปผลทีม
        ↓
หัวหน้ายืนยัน → ใช้ประกอบ Merit-to-Earn (ผลตอบแทน)
```

| ลำดับ | หน้าที่ | สิ่งที่ระบบทำตอนนี้ |
|-------|---------|-------------------|
| 1 | รวบรวมข้อมูล | บันทึกงานรายวันและหลักฐานในโปรเจกต์ |
| 2 | แจ้งเตือน | บอกจุดติดขัด และแนวทางตรวจข้อความผิดปกติ |
| 3 | อำนวยความสะดวก | รวมสถานะโปรเจกต์และลิงก์เอกสาร Google |
| 4 | ประเมินแบบเป็นกลาง | ให้ Impact Score 0–10 พร้อมเหตุผล ผูกกับ Milestone/KPI คำนวณสัดส่วนรวม 100% และสรุปทีม |

รายละเอียด: [ทีม-AI-ขอบเขตหน้าที่.md](./ทีม-AI-ขอบเขตหน้าที่.md)

## 5. ผู้ใช้และสิทธิ์

| บทบาท | สิทธิ์หลัก |
|-------|------------|
| สมาชิก (พนักงาน) | บันทึกงาน ดูโปรเจกต์ของตน ดูคะแนนและเหตุผล |
| หัวหน้าโปรเจกต์ | ดูภาพรวมทีม อัปเดตสรุป ยืนยันคะแนน (รอบถัดไป: ส่งลิงก์เชิญ) |
| ผู้ดูแลระบบ / ฝ่ายบุคคล | ดูแลโครงสร้างองค์กรและข้อมูลประกอบรางวัล (รอบถัดไป) |

กฎสำคัญ: สมาชิกใหม่ในองค์กรควรเข้าผ่านลิงก์เชิญ ไม่สมัครเปิดสาธารณะเอง  
รายละเอียด: [ข้อกำหนด-เชิญสมาชิก.md](./ข้อกำหนด-เชิญสมาชิก.md)

## 6. ขั้นตอนการใช้งานหลัก

1. ผู้ใช้เข้าสู่ระบบ
2. สร้างหรือเปิดโปรเจกต์ และกำหนดวัตถุประสงค์ / เป้าหมายงานส่งมอบ / ตัวชี้วัด (พร้อมค่าน้ำหนัก)
3. บันทึกงานที่ทำในวันนั้น (สิ่งที่ทำสำเร็จ และปัญหาที่ติด) — ใช้เป็นหลักฐาน
4. ระบบเทียบหลักฐานกับเป้าหมาย ให้ Impact Score พร้อมเหตุผล
5. ความคืบหน้าโครงการรวม และสัดส่วนผลงานรายบุคคลอัปเดตบนหน้าสรุป
6. หัวหน้าดูสรุปทีม ยืนยันคะแนน/สัดส่วน แล้วนำไปใช้คุยงานหรือประกอบรางวัล
7. **รอบถัดไป:** เชื่อมผลตอบแทนจริง (โบนัส / สวัสดิการ) โดยคนเป็นผู้ตัดสิน

## 7. โครงระบบตอนนี้ (อธิบายแบบภาษางานทั่วไป)

ระบบที่เปิดใช้งานจริงตอนนี้ประกอบด้วยส่วนหลักดังนี้

| ส่วน | ใช้ทำอะไร | เทคโนโลยีที่ใช้ |
|------|-----------|-----------------|
| หน้าเว็บ | ให้คนใช้งานผ่านเบราว์เซอร์ | Next.js |
| การเข้าสู่ระบบ | ยืนยันตัวตนด้วยอีเมลหรือบัญชี Google | Firebase Authentication |
| ฐานข้อมูล | เก็บโปรเจกต์ บันทึกงาน คะแนน | Cloud Firestore (แยกข้อมูลรายผู้ใช้) |
| สมองกล AI | อ่านงาน ให้คะแนน อธิบายเหตุผล สรุปทีม | Google Gemini |
| การติดตั้งบนคลาวด์ | ให้เปิดใช้ผ่านอินเทอร์เน็ต | Google Cloud Run |

**หมายเหตุเรื่องสองชุดข้อมูลในโปรเจกต์**

- **ชุดที่ใช้งานจริงตอนนี้:** Firebase / Firestore / Gemini  
- **ชุดเตรียมสำหรับองค์กรรอบถัดไป:** Prisma / PostgreSQL และการเชิญสมาชิกด้วยลิงก์  

ทั้งสองชุดอยู่ในที่เก็บโค้ดเดียวกัน พิมพ์เขียวนี้ถือว่าชุด Firebase เป็นต้นทางของเวอร์ชันต้นแบบที่ deploy แล้ว

## 8. สิ่งที่ทำแล้ว และสิ่งที่เลื่อน

รายการสำรวจล่าสุด: [สถานะแพลตฟอร์ม.md](./สถานะแพลตฟอร์ม.md) (6 ก.ย. 2026)

### ทำแล้ว (เวอร์ชันต้นแบบที่เปิดใช้จริง)

- เข้าสู่ระบบด้วย Google หรืออีเมล (Firebase Auth)
- พื้นที่โปรเจกต์ส่วนรวม และบันทึกงานรายวัน (ข้อมูลแยกรายผู้ใช้ใน Firestore)
- ผู้ช่วย AI ให้คะแนน 0–10 พร้อมเหตุผล และแชทในบริบทโปรเจกต์
- หน้าสรุปความคืบหน้าและคะแนนสะสม
- สรุปภาพรวมทีมจากบันทึกงาน
- ลิงก์เอกสาร Google ในโปรเจกต์
- Deploy บน Cloud Run
- กฎไม่แตะข้อความส่วนตัว (ในเอกสารผลิตภัณฑ์และคำสั่ง AI)
- ล็อกเกณฑ์เปอร์เซ็นต์ 2 มิติในเอกสารผลิตภัณฑ์ (ยึด Objectives / Milestones / KPIs)

### ทำบางส่วน

- ประวัติคะแนนที่ย้อนดูได้ (มีเหตุผลในบันทึกงาน)
- การโต้แย้งคะแนน (มีในเอกสารและโครง Prisma)
- การเชิญสมาชิกองค์กร (มีเอกสารและโครงโค้ด — ยังไม่ต่อกับ Firebase login)
- ความคืบหน้า % บนแดชบอร์ด — ยังไม่ผูกน้ำหนัก Milestone / KPI ครบตามเกณฑ์ใหม่
- สัดส่วนรายบุคคลรวม 100% — ล็อกในเอกสารแล้ว รอลงโค้ดและข้อมูลจริง
- หน้าหลักฐาน / แจ้งเตือน / ประเมินบน Prisma — มีแล้วแต่ใช้ NextAuth คนละเส้นทางกับหน้าแรก

### เลื่อนไว้รอบถัดไป

- จ่ายโบนัสหรือเชื่อมระบบเงินเดือนอัตโนมัติ
- พื้นที่พิมพ์งานแบบบล็อกคล้าย Notion ทั้งระบบ
- ติดตั้งบนคลาวด์ส่วนตัวของลูกค้า
- บัญชีองค์กร Microsoft 365
- เหรียญรางวัลดิจิทัล / บล็อกเชน

หลักการเวอร์ชันต้นแบบ: **ทำให้คะแนนและสัดส่วนโปร่งใส ตรวจสอบได้ และผูกกับเป้าหมายโครงการก่อน แล้วค่อยเชื่อมผลตอบแทน**

## สรุปสั้นหนึ่งย่อหน้า

ARWEEN คือระบบช่วยให้งานในโปรเจกต์ถูกบันทึกและประเมินอย่างโปร่งใส โดยยึดวัตถุประสงค์ เป้าหมายงานส่งมอบ และตัวชี้วัดเป็นตัวตั้ง ให้ผู้ช่วยปัญญาประดิษฐ์ทำงานเบื้องหลัง ให้คะแนนผลกระทบพร้อมเหตุผล คำนวณความคืบหน้าโครงการและสัดส่วนผลงานรายบุคคล เพื่อให้งานเบื้องหลังถูกมองเห็น และในอนาคตนำไปสู่ผลตอบแทนที่เป็นธรรม โดยหัวหน้ายังเป็นผู้ตัดสิน ไม่ใช่ระบบจ่ายเงินเองในเวอร์ชันต้นแบบ
