# เกณฑ์เปอร์เซ็นต์การทำงาน

**ต้นทางผลิตภัณฑ์:** [พิมพ์เขียว-ARWEEN.md](./พิมพ์เขียว-ARWEEN.md) · [ข้อมูลหลัก-ARWEEN.md](./ข้อมูลหลัก-ARWEEN.md)

เอกสารนี้ล็อกวิธีคำนวณ “เปอร์เซ็นต์การทำงาน” ของ ARWEEN  
ภาษาที่ใช้: ไทย กึ่งทางการ เข้าใจง่าย

---

## 1. หลักการ

**ประเมินจากผลลัพธ์ที่มีคุณค่า ไม่ใช่จากปริมาณกิจกรรม**  
(Outcome-driven over Activity-driven)

ปัญหาที่ต้องการเลี่ยง: ความลำเอียงจากปริมาณกิจกรรม (Activity Bias) เช่น พิมพ์ข้อความบ่อยหรืออัปเดตสถานะถี่แล้วได้เปอร์เซ็นต์สูง ทั้งที่งานนั้นไม่ได้ช่วยเป้าหมายองค์กร

**ตัวตั้งหลัก (Anchor Framework)** ของทุกการคำนวณ:

1. **วัตถุประสงค์ (Objectives)** — โปรเจกต์ต้องการบรรลุอะไร
2. **เป้าหมายงานส่งมอบ (Milestones)** — งานส่งมอบสำคัญตามแผน
3. **ตัวชี้วัดความสำเร็จ (KPIs)** — วัดว่าสำเร็จอย่างไร

**บทบาทของบันทึกงานรายวัน (Daily Logs) และการแชทแก้ปัญหาในพื้นที่โปรเจกต์ส่วนรวม**  
ไม่ใช่ตัวตั้งคะแนนโดยตรง แต่เป็น **หลักฐานเชิงประจักษ์ (Evidence)** เพื่อพิสูจน์ว่ากิจกรรมนั้นช่วยขับเคลื่อนวัตถุประสงค์ / เป้าหมาย / ตัวชี้วัดใด

## 2. กลไกเปอร์เซ็นต์ 2 มิติ

### 2.1 มิติความคืบหน้าโครงการรวม (Project Progress: 0–100%)

| หัวข้อ | รายละเอียด |
|--------|------------|
| เกณฑ์ | กำหนดค่าน้ำหนัก (Weight) ให้แต่ละวัตถุประสงค์ งานส่งมอบ และตัวชี้วัด ตามโครงสร้างแผนงาน |
| การคำนวณ | เมื่อเงื่อนไขของงานส่งมอบ (Deliverable) หรือตัวชี้วัดย่อยสำเร็จ ความคืบหน้ารวมบนแดชบอร์ดขยับตามสัดส่วนน้ำหนักของความสำเร็จนั้น |
| ผลลัพธ์ที่เห็น | หลอดความคืบหน้าภาพรวม (Progress Bar) 0–100% |

### 2.2 มิติสัดส่วนผลงานรายบุคคล (Contribution Ratio: รวมกันครบ 100%)

| หัวข้อ | รายละเอียด |
|--------|------------|
| เกณฑ์ | วัดระดับผลกระทบ (Impact Level) ที่การกระทำของสมาชิกแต่ละคนมีต่อความสำเร็จของ Milestone และตัวชี้วัด |
| การคำนวณ | ระบบให้คะแนนผลกระทบ (Impact Score 0–10) แล้วรวบรวมคะแนนทุกคนมาแปลงเป็นสัดส่วนที่รวมกันได้ 100% พอดี |
| ตัวอย่าง | การแก้คอขวดสำคัญ (Critical Blocker) ได้คะแนนผลกระทบสูง |
| การใช้ต่อ | เป็นข้อมูลประกอบผลตอบแทนตามกลไก Merit-to-Earn — หัวหน้ายังยืนยันก่อนใช้จริง |

## 3. Multi-Agent ที่เชื่อมงานหน้างานกับตัวชี้วัด

ขับเคลื่อนด้วย Multi-Agent System (Google Gemini) ในกรอบหน้าที่สี่ข้อของทีม AI

| Agent | ชื่อในระบบ | ทำอะไร |
|-------|------------|--------|
| Agent 1 | Context Analyzer & Milestone Mapper | รับบันทึกงานและข้อความแก้ปัญหาใน Workspace มาเทียบกับตารางเป้าหมายและ KPIs — งานทั่วไปได้ Impact Score 0–3; ช่วยปลดล็อก Blocker ของ KPI หลักได้ 8–10 พร้อมเหตุผล (AI Rationale) |
| Agent 2 | Contribution Calculator | นำ Impact Score ของทุกคนที่ผูกกับตัวชี้วัด มาแปลงเป็นสัดส่วนการมีส่วนร่วมรวม 100% |
| Agent 3 | Fraud & Bias Detector | ตรวจและระงับการสร้างกิจกรรมซ้ำ ๆ ที่ไม่มีผลต่อความสำเร็จของตัวชี้วัด (Anti-Gaming Policy) |

## 4. กฎที่ต้องยึดร่วมกัน

1. ไม่ให้เปอร์เซ็นต์จากจำนวนข้อความหรือความถี่อัปเดตอย่างเดียว  
2. ทุก Impact Score ต้องผูกกับวัตถุประสงค์ / Milestone / KPI อย่างน้อยหนึ่งรายการ และมีเหตุผล  
3. ความคืบหน้าโครงการรวมคำนวณจากน้ำหนักแผนงาน ไม่ใช่จากจำนวนบันทึกรายวัน  
4. สัดส่วนรายบุคคลในรอบที่ปิดแล้วต้องรวมได้ 100%  
5. ระบบไม่จ่ายโบนัสเอง — ส่งสัดส่วนและเหตุผลให้คนตัดสิน
