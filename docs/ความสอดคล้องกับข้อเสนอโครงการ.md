# ความสอดคล้องกับข้อเสนอโครงการ ARWEEN

**ต้นทางผลิตภัณฑ์:** [พิมพ์เขียว-ARWEEN.md](./พิมพ์เขียว-ARWEEN.md) · [ข้อมูลหลัก-ARWEEN.md](./ข้อมูลหลัก-ARWEEN.md)

เอกสารนี้เทียบ [บทที่ 1–5 ข้อเสนอโครงการ](../บทที่%201%20บทนำ%20-%20โครงการ%20ARWEEN.pdf) กับสิ่งที่สร้างในโปรเจกต์ตอนนี้ เพื่อให้ทีมอ่านแล้วเข้าใจตรงกันว่าอะไรทำแล้ว อะไรทำบางส่วน และอะไรเก็บไว้รอบถัดไป

รายการสำรวจโค้ดล่าสุด: [สถานะแพลตฟอร์ม.md](./สถานะแพลตฟอร์ม.md) (6 ก.ย. 2026)

## วิสัยทัศน์จากข้อเสนอ (ไม่เปลี่ยน)

| หัวข้อ | เนื้อหาจากข้อเสนอ |
|--------|-------------------|
| ชื่อ | ARWEEN: Superior Operations Management Cycle |
| ปัญหาหลัก | ประเมินผลไม่โปร่งใส งานเบื้องหลังไม่ถูกมองเห็น (ปิดทองหลังพระ) Workspace กับ HR แยกกัน |
| หลักการ | การทำดีอย่างมีคุณภาพ ต้องได้รับผลตอบแทนที่เหนือกว่า |
| กลไกหลัก | Invisible AI Observer + Merit-to-Earn + Audit Trail |
| กลุ่มเป้าหมาย | B2B — องค์กรขนาดกลาง–ใหญ่, องค์กรแบบโปรเจกต์, C-Level / HR |

---

## คำศัพท์ที่ต้องใช้ร่วมกัน

| คำในข้อเสนอ | ความหมายในโปรเจกต์นี้ |
|-------------|----------------------|
| Invisible AI Observer | ทีม AI สี่หน้าที่ที่ทำงานเบื้องหลัง ไม่บังคับให้พนักงานเขียนรายงานแยก |
| High Impact Action | การกระทำที่มีผลต่อความสำเร็จของ Milestone / KPI สูง ได้คะแนนสูงกว่าข้อความทั่วไป |
| Merit-to-Earn | เปลี่ยนคะแนน/สัดส่วนความทุ่มเทเป็นข้อมูลประกอบรางวัล — รอบนี้ยังไม่จ่ายเงินอัตโนมัติ |
| Audit Trail | ประวัติหลักฐานและเหตุผลการให้คะแนน ตรวจสอบและโต้แย้งได้ |
| Multi-Agent | แบ่งงาน AI: เทียบงานกับเป้าหมาย, คำนวณสัดส่วนรวม 100%, ตรวจสัญญาณผิดปกติ |
| Anchor Framework | ตัวตั้งหลัก: วัตถุประสงค์, เป้าหมายงานส่งมอบ, ตัวชี้วัดความสำเร็จ |

## ตารางเทียบ: ข้อเสนอ ↔ ของที่ทำแล้ว

| จากข้อเสนอ | สถานะในโปรเจกต์ | รายละเอียด |
|------------|-----------------|------------|
| พื้นที่ทำงานโปรเจกต์ส่วนรวม | ทำแล้ว (MVP) | สร้าง/ดูโปรเจกต์ บันทึกงานรายวัน อ้างอิงเอกสาร Google |
| AI สังเกตการณ์เบื้องหลัง | ทำแล้วบางส่วน | Gemini ประเมินบันทึกงาน ให้คะแนน + เหตุผล ไม่แตะข้อความส่วนตัว |
| แปลงพฤติกรรมเป็นตัวเลข | ทำแล้วบางส่วน | Impact Score 0–10 ตามผลต่อ Milestone/KPI; สัดส่วนรวม 100% ล็อกในเอกสาร รอลงโค้ดครบ |
| Merit-to-Earn / โบนัสอัตโนมัติ | ยังไม่ทำ | มีคะแนนและเหตุผลให้หัวหน้าใช้ประกอบ — ยังไม่เชื่อมเงินเดือน |
| Audit Trail + Dispute | ทำแล้วบางส่วน | เก็บเหตุผลคะแนนในบันทึกงาน; หน้าโต้แย้งมีในโครง Prisma/docs |
| ห้ามอ่าน DM | ล็อกในเอกสารและกฎผลิตภัณฑ์ | ประมวลผลเฉพาะพื้นที่โปรเจกต์ส่วนรวม |
| Multi-Agent 3 ตัว | ทำแนวคิดใน Gemini + docs | Mapper / Calculator / Fraud Detector — ยังไม่แยกบริการ 3 โปรเซสอิสระ |
| Live Contribution Dashboard | ทำแล้วบางส่วน | ความคืบหน้า % และคะแนนสะสม; ยังไม่ผูกน้ำหนัก Milestone/KPI ครบ |
| เกณฑ์เปอร์เซ็นต์ 2 มิติ (Progress + Contribution) | ล็อกในเอกสารแล้ว | ดู [เกณฑ์เปอร์เซ็นต์การทำงาน.md](./เกณฑ์เปอร์เซ็นต์การทำงาน.md) |
| Block-based Workspace แบบ Notion | ยังไม่ทำ | MVP ใช้บันทึกรายวัน + ลิงก์เอกสาร ไม่สร้าง editor ใหม่ |
| เชิญสมาชิกองค์กร / SSO | ทำแล้วในเอกสารและโครงเชิญ | โฟลว์เชิญ + Google; แอปที่ deploy ใช้ Firebase Auth |
| Private Cloud / On-Premise | ยังไม่ทำ | Deploy บน Cloud Run เป็นต้นแบบ |
| Blockchain / Token ปี 2 | ยังไม่ทำ | ตามข้อเสนอ — เลื่อนทั้งหมด |

## หน้าที่ทีม AI ที่ล็อกแล้ว เทียบกับ Agent ในข้อเสนอ

| หน้าที่ในโปรเจกต์ | Agent ในข้อเสนอ | งานที่ทำ |
|-------------------|-----------------|----------|
| 1. รวบรวมข้อมูล | ส่วนของ Data / Ingestion | เก็บใครทำอะไร เมื่อไหร่ ในโปรเจกต์ส่วนรวม |
| 2. แจ้งเตือน | ส่วนของ Fraud Detector | สรุปรายสัปดาห์, สัญญาณปั่นคะแนน, ข้อโต้แย้งค้าง |
| 3. อำนวยความสะดวก | Workspace + Integration | รวมสถานะ เอกสาร ลิงก์ Google ไว้ที่เดียว |
| 4. ประเมินแบบเป็นกลาง | Agent 1 Mapper + Agent 2 Calculator | Impact Score ผูกเป้าหมาย + สัดส่วนรวม 100% + สรุปทีม; คนยืนยันก่อนใช้ประกอบรางวัล |

---

## หลักการปรับให้สอดคล้องโดยไม่ทำเกิน MVP

1. **คงวิสัยทัศน์ข้อเสนอครบ** ในเอกสารและคำอธิบายผลิตภัณฑ์  
2. **MVP พิสูจน์ความโปร่งใสของคะแนน** ที่ผูกกับ Objectives / Milestones / KPIs ก่อนเชื่อมจ่ายเงิน  
3. **ล็อกสัดส่วนผลงานรายบุคคลรวม 100%** ในเกณฑ์ผลิตภัณฑ์ — ลงโค้ดและข้อมูลจริงเป็นขั้นถัดไป  
4. **หัวหน้ายังเป็นผู้ตัดสินสุดท้าย** ตามหลัก Audit Trail และ Dispute ในข้อเสนอ
