# 1. ภาพรวมผลิตภัณฑ์

**หลักการสำคัญ:** การทำดีอย่างมีคุณภาพ ต้องได้รับผลตอบแทนที่เหนือกว่า

## ARWEEN คืออะไร

ระบบช่วยองค์กรบันทึกงานในโปรเจกต์ ให้ระบบช่วยวิเคราะห์และให้คะแนนอย่างโปร่งใส พร้อมเหตุผลที่ย้อนดูได้ เพื่อให้งานเบื้องหลังถูกมองเห็น และนำไปใช้ประกอบการให้รางวัลอย่างเป็นธรรม

## ปัญหาที่ต้องการแก้

1. การประเมินผลงานไม่โปร่งใส หัวหน้ามักประเมินจากความทรงจำหรือรายงานท้ายปี
2. คนที่ทำงานเบื้องหลัง (ปิดทองหลังพระ) ไม่ถูกบันทึกผลงาน
3. ระบบทำงานประจำวัน กับระบบบุคคล (HR) แยกกัน
4. ความทุ่มเทไม่สอดคล้องกับผลตอบแทน ทำให้หมดไฟและลาออก

## ใครใช้

| กลุ่ม | ใช้ทำอะไร |
|-------|-----------|
| พนักงาน | บันทึกงานในโปรเจกต์ ดูคะแนนและเหตุผล |
| หัวหน้าโปรเจกต์ | ดูความคืบหน้า ยืนยันคะแนน สรุปทีม |
| ผู้บริหาร / ฝ่ายบุคคล | ใช้ข้อมูลประกอบการพิจารณาโบนัสหรือเลื่อนตำแหน่ง |

รูปแบบธุรกิจ: ขายให้องค์กร (B2B) โดยเฉพาะบริษัทขนาดกลางถึงใหญ่ และองค์กรที่ทำงานเป็นโปรเจกต์

# 2. คำสำคัญ

| คำ | ความหมายภาษาไทยง่าย ๆ |
|----|------------------------|
| Invisible AI Observer | ผู้ช่วยปัญญาประดิษฐ์ที่ทำงานเบื้องหลัง ช่วยดูและให้คะแนนงานโดยไม่บังคับให้พนักงานเขียนรายงานแยก |
| High Impact Action | งานที่มีผลต่อโปรเจกต์สูง เช่น แก้ปัญหาซับซ้อน หรือช่วยทีมข้ามแผนก |
| Merit-to-Earn | การเปลี่ยนคะแนนความทุ่มเทเป็นผลตอบแทน เช่น โบนัสหรือวันหยุด — เวอร์ชันต้นแบบยังไม่จ่ายเงินอัตโนมัติ |
| Audit Trail | ประวัติการให้คะแนนที่ย้อนดูได้ รู้ว่าคะแนนมาจากงานไหนและเหตุผลอะไร |
| Multi-Agent | การแบ่งงานให้ระบบ AI หลายส่วนช่วยกัน เช่น เทียบงานกับเป้าหมาย ให้คะแนน สรุปสัดส่วน ตรวจพฤติกรรมผิดปกติ |
| Anchor Framework | ตัวตั้งหลักของการประเมิน: วัตถุประสงค์ (Objectives), เป้าหมายงานส่งมอบ (Milestones), ตัวชี้วัด (KPIs) |
| Impact Score | คะแนนผลกระทบ 0–10 ที่ผูกกับ Milestone / KPI ไม่ใช่จากจำนวนข้อความ |
| Contribution Ratio | สัดส่วนผลงานรายบุคคลที่รวมกันครบ 100% ใช้ประกอบ Merit-to-Earn |
| Dispute | การยื่นโต้แย้งคะแนน เมื่อพนักงานไม่เห็นด้วย |
| Activity Bias | ความลำเอียงจากปริมาณกิจกรรม เช่น พิมพ์บ่อยแล้วได้คะแนนสูงโดยงานไม่ช่วยเป้าหมาย |
| Anti-Gaming Policy | นโยบายป้องกันการปั่นคะแนนด้วยกิจกรรมที่ไม่มีผลต่อตัวชี้วัด |

# 3. เกณฑ์เปอร์เซ็นต์การทำงาน

## 3.1 หลักการ

**ประเมินจากผลลัพธ์ที่มีคุณค่า ไม่ใช่จากปริมาณกิจกรรม**  
(Outcome-driven over Activity-driven)

ปัญหาที่ต้องการเลี่ยง: ความลำเอียงจากปริมาณกิจกรรม (Activity Bias) เช่น พิมพ์ข้อความบ่อยหรืออัปเดตสถานะถี่แล้วได้เปอร์เซ็นต์สูง ทั้งที่งานนั้นไม่ได้ช่วยเป้าหมายองค์กร

**ตัวตั้งหลัก (Anchor Framework)** ของทุกการคำนวณ:

1. **วัตถุประสงค์ (Objectives)** — โปรเจกต์ต้องการบรรลุอะไร
2. **เป้าหมายงานส่งมอบ (Milestones)** — งานส่งมอบสำคัญตามแผน
3. **ตัวชี้วัดความสำเร็จ (KPIs)** — วัดว่าสำเร็จอย่างไร

**บทบาทของบันทึกงานรายวัน (Daily Logs) และการแชทแก้ปัญหาในพื้นที่โปรเจกต์ส่วนรวม**  
ไม่ใช่ตัวตั้งคะแนนโดยตรง แต่เป็น **หลักฐานเชิงประจักษ์ (Evidence)** เพื่อพิสูจน์ว่ากิจกรรมนั้นช่วยขับเคลื่อนวัตถุประสงค์ / เป้าหมาย / ตัวชี้วัดใด

## 3.2 กลไกเปอร์เซ็นต์ 2 มิติ

### มิติ A — ความคืบหน้าโครงการรวม (Project Progress: 0–100%)

| หัวข้อ | รายละเอียด |
|--------|------------|
| เกณฑ์ | กำหนดค่าน้ำหนัก (Weight) ให้แต่ละวัตถุประสงค์ งานส่งมอบ และตัวชี้วัด ตามโครงสร้างแผนงาน |
| การคำนวณ | เมื่อเงื่อนไขของงานส่งมอบ (Deliverable) หรือตัวชี้วัดย่อยสำเร็จ ความคืบหน้ารวมบนแดชบอร์ดขยับตามสัดส่วนน้ำหนักของความสำเร็จนั้น |
| ผลลัพธ์ที่เห็น | หลอดความคืบหน้าภาพรวม (Progress Bar) 0–100% |

### มิติ B — สัดส่วนผลงานรายบุคคล (Contribution Ratio: รวมกันครบ 100%)

| หัวข้อ | รายละเอียด |
|--------|------------|
| เกณฑ์ | วัดระดับผลกระทบ (Impact Level) ที่การกระทำของสมาชิกแต่ละคนมีต่อความสำเร็จของ Milestone และตัวชี้วัด |
| การคำนวณ | ระบบให้คะแนนผลกระทบ (Impact Score 0–10) แล้วรวบรวมคะแนนทุกคนมาแปลงเป็นสัดส่วนที่รวมกันได้ 100% พอดี |
| ตัวอย่าง | การแก้คอขวดสำคัญ (Critical Blocker) ได้คะแนนผลกระทบสูง |
| การใช้ต่อ | เป็นข้อมูลประกอบผลตอบแทนตามกลไก Merit-to-Earn — หัวหน้ายังยืนยันก่อนใช้จริง |

## 3.3 Multi-Agent ที่เชื่อมงานหน้างานกับตัวชี้วัด

ขับเคลื่อนด้วย Multi-Agent System (Google Gemini) ในกรอบหน้าที่สี่ข้อของทีม AI

| Agent | ชื่อในระบบ | ทำอะไร |
|-------|------------|--------|
| Agent 1 | Context Analyzer & Milestone Mapper | รับบันทึกงานและข้อความแก้ปัญหาใน Workspace มาเทียบกับตารางเป้าหมายและ KPIs — งานทั่วไปได้ Impact Score 0–3; ช่วยปลดล็อก Blocker ของ KPI หลักได้ 8–10 พร้อมเหตุผล (AI Rationale) |
| Agent 2 | Contribution Calculator | นำ Impact Score ของทุกคนที่ผูกกับตัวชี้วัด มาแปลงเป็นสัดส่วนการมีส่วนร่วมรวม 100% |
| Agent 3 | Fraud & Bias Detector | ตรวจและระงับการสร้างกิจกรรมซ้ำ ๆ ที่ไม่มีผลต่อความสำเร็จของตัวชี้วัด (Anti-Gaming Policy) |

## 3.4 กฎที่ต้องยึดร่วมกัน

1. ไม่ให้เปอร์เซ็นต์จากจำนวนข้อความหรือความถี่อัปเดตอย่างเดียว
2. ทุก Impact Score ต้องผูกกับวัตถุประสงค์ / Milestone / KPI อย่างน้อยหนึ่งรายการ และมีเหตุผล
3. ความคืบหน้าโครงการรวมคำนวณจากน้ำหนักแผนงาน ไม่ใช่จากจำนวนบันทึกรายวัน
4. สัดส่วนรายบุคคลในรอบที่ปิดแล้วต้องรวมได้ 100%
5. ระบบไม่จ่ายโบนัสเอง — ส่งสัดส่วนและเหตุผลให้คนตัดสิน

# 4. วงจรทำงาน 4 หน้าที่ของทีม AI

ระบบ AI ใน ARWEEN ทำได้เฉพาะสี่งานนี้ ตามลำดับ

```
งานเกิดในพื้นที่โปรเจกต์ส่วนรวม
        ↓
1. รวบรวมข้อมูล — เก็บว่าใครทำอะไร เมื่อไหร่
        ↓
2. แจ้งเตือน — สรุปรายสัปดาห์ / สัญญาณปั่นคะแนน / ข้อโต้แย้งค้าง
        ↓
3. อำนวยความสะดวก — รวมสถานะงานและเอกสารไว้ที่เดียว
        ↓
4. ประเมินแบบเป็นกลาง — Impact Score + ความคืบหน้า + สัดส่วน 100% + สรุปทีม
        ↓
หัวหน้ายืนยัน → ใช้ประกอบ Merit-to-Earn (ผลตอบแทน)
```

| ลำดับ | หน้าที่ | สรุปสั้น | เชื่อมกับข้อเสนอ |
|-------|---------|----------|-----------------|
| 1 | รวบรวมข้อมูล | เก็บหลักฐานในโปรเจกต์ส่วนรวม: ใครทำอะไร เมื่อไหร่ | Audit Trail / Workspace ส่วนรวม |
| 2 | แจ้งเตือน | สรุปงานรายสัปดาห์, สัญญาณปั่นคะแนน, ข้อโต้แย้งที่ยังไม่ปิด | Fraud Detection + ความโปร่งใส |
| 3 | อำนวยความสะดวก | รวมเอกสาร อัปเดตสถานะงาน รวมข้อมูลที่กระจัดกระจายไว้ที่เดียว | ลดภาระเขียนรายงาน |
| 4 | ประเมินแบบเป็นกลาง | ให้ Impact Score จากผลต่อ Milestone/KPI อ้างหลักฐาน คำนวณสัดส่วนรวม 100% สรุปผลทีม | Agent 1 Mapper + Agent 2 Calculator |

## สิ่งที่ทีม AI ห้ามทำ

- อ่านหรือเก็บข้อความส่วนตัว (DM, แชทส่วนตัว, อีเมลส่วนตัว)
- เขียนงานแทนพนักงาน
- จ่ายโบนัสหรือเงินอัตโนมัติในรอบ MVP
- ค้นข้อมูลทั่วไป เขียนบทความ หรือช่วยเขียนโปรแกรมนอกวงจร ARWEEN
- แจ้งทุกข้อความหรือจัดอันดับประจาน
- นับจำนวนคำแทนคุณภาพงาน (ต้องใช้หลักผลต่อ Milestone / KPI และ High Impact Action)

ประเมินไม่ได้ถ้ายังไม่มีหลักฐาน และควรมีโครงเป้าหมาย (Objectives / Milestones / KPIs) เป็นตัวตั้ง  
ระบบไม่จ่ายโบนัสเองใน MVP — ส่งข้อมูลที่ตรวจสอบได้ให้คนตัดสิน

# 5. ผู้ใช้และสิทธิ์

| บทบาท | สิทธิ์หลัก |
|-------|------------|
| สมาชิก (พนักงาน) | บันทึกงาน ดูโปรเจกต์ของตน ดูคะแนนและเหตุผล |
| หัวหน้าโปรเจกต์ | ดูภาพรวมทีม อัปเดตสรุป ยืนยันคะแนน (รอบถัดไป: ส่งลิงก์เชิญ) |
| ผู้ดูแลระบบ / ฝ่ายบุคคล | ดูแลโครงสร้างองค์กรและข้อมูลประกอบรางวัล (รอบถัดไป) |

กฎสำคัญ: สมาชิกใหม่ในองค์กรควรเข้าผ่านลิงก์เชิญ ไม่สมัครเปิดสาธารณะเอง

# 6. ขั้นตอนการใช้งานหลัก

1. ผู้ใช้เข้าสู่ระบบ
2. สร้างหรือเปิดโปรเจกต์ และกำหนดวัตถุประสงค์ / เป้าหมายงานส่งมอบ / ตัวชี้วัด (พร้อมค่าน้ำหนัก)
3. บันทึกงานที่ทำในวันนั้น (สิ่งที่ทำสำเร็จ และปัญหาที่ติด) — ใช้เป็นหลักฐาน
4. ระบบเทียบหลักฐานกับเป้าหมาย ให้ Impact Score พร้อมเหตุผล
5. ความคืบหน้าโครงการรวม และสัดส่วนผลงานรายบุคคลอัปเดตบนหน้าสรุป
6. หัวหน้าดูสรุปทีม ยืนยันคะแนน/สัดส่วน แล้วนำไปใช้คุยงานหรือประกอบรางวัล
7. **รอบถัดไป:** เชื่อมผลตอบแทนจริง (โบนัส / สวัสดิการ) โดยคนเป็นผู้ตัดสิน

## 8.11 กฎที่ผูกกับข้อมูลหลัก

1. **ห้ามเก็บข้อความส่วนตัว** — ระบบเก็บได้เฉพาะงานในพื้นที่โปรเจกต์ส่วนรวม
2. **คะแนนต้องมีเหตุผลและผูกเป้าหมาย** — ห้ามมี Impact Score ลอย ๆ โดยไม่อธิบาย
3. **บันทึกงานคือหลักฐาน ไม่ใช่ตัวตั้งคะแนน** — ปริมาณข้อความไม่ใช่เกณฑ์เปอร์เซ็นต์
4. **ความคืบหน้าโครงการรวมคำนวณจากน้ำหนักแผนงาน** — เมื่อ Deliverable / KPI สำเร็จ
5. **สัดส่วนผลงานรายบุคคลรวมได้ 100%** — แปลงจาก Impact Score ของสมาชิกในรอบนั้น
6. **ลิงก์เชิญใช้ครั้งเดียว** — หมดอายุภายใน 7 วัน
7. **ระบบไม่จ่ายโบนัสเองในเวอร์ชันต้นแบบ** — หัวหน้าหรือฝ่ายบุคคลเป็นผู้ตัดสิน
8. **งานเบื้องหลังที่มีผลจริงต่อตัวชี้วัด ให้คะแนนสูงได้** — ไม่ดูแค่ว่างานนั้นคนเห็นง่ายหรือไม่
9. **ห้ามปั่นคะแนนด้วยกิจกรรมที่ไม่มีผลต่อ KPI** — Agent 3 ตั้งธงและระงับน้ำหนัก

# 12. ข้อกำหนดหน้าที่ที่ 4 — ประเมินแบบเป็นกลาง

หน้าที่ที่ 4 ของทีม AI — ให้คะแนนและสรุปผลทีมจากหลักฐานจริง โดยยึดวัตถุประสงค์ / เป้าหมายงานส่งมอบ / ตัวชี้วัดเป็นตัวตั้ง

## ผลลัพธ์ต้องมีครบชุดนี้

### 1. Impact Score รายหลักฐาน (Agent 1)

| ฟิลด์ | ความหมาย |
|-------|----------|
| คะแนนผลกระทบ | 0–10 ตามผลต่อ Milestone / KPI (งานทั่วไป 0–3; ปลดล็อก Blocker ของ KPI หลัก 8–10) |
| เหตุผล | อธิบายว่าทำไมได้คะแนนนี้ และผูกกับเป้าหมายใด |
| หลักฐาน | อ้างบันทึกงาน / ข้อความในพื้นที่โปรเจกต์ส่วนรวม |

### 2. สองมิติเปอร์เซ็นต์

| มิติ | ผลลัพธ์ |
|------|---------|
| Project Progress | ความคืบหน้าโครงการรวม 0–100% จากน้ำหนักแผนงานเมื่อ Deliverable / KPI สำเร็จ |
| Contribution Ratio | สัดส่วนผลงานรายบุคคลที่รวมกันครบ 100% จาก Impact Score (Agent 2) |

### 3. สรุปผลงานทั้งทีม

- สิ่งที่ทีมทำสำเร็จเทียบกับเป้าหมาย
- ปัญหาที่ยังค้าง (Blockers)
- ข้อสังเกตจากหลักฐานรวม
- สัญญาณปั่นคะแนน (ถ้ามี จาก Agent 3)

## หลักการ

- ประเมินจากผลลัพธ์ที่มีคุณค่า ไม่ใช่ปริมาณกิจกรรม
- ใช้เกณฑ์ชุดเดียวกันกับทุกคน เพื่อลดอคติจากความชอบของหัวหน้า
- อ้างได้เฉพาะงานที่มีหลักฐานในพื้นที่โปรเจกต์ส่วนรวม
- หัวหน้ายืนยันก่อนใช้ประกอบรางวัล (Merit-to-Earn) — ระบบไม่ปิดเคสโบนัสเอง
- พนักงานดูที่มาของคะแนน/สัดส่วนและยื่นข้อโต้แย้ง (Dispute) ได้ตามหลัก Audit Trail

## สิ่งที่ห้ามทำ

- ให้คะแนนจากจำนวนข้อความแทนผลต่อตัวชี้วัด
- มีแต่จัดอันดับบุคคล ไม่มีสรุปผลทีมและความคืบหน้าโครงการ
- ตัดสินเงินหรือโบนัสอัตโนมัติ
- ประเมินจากข้อความส่วนตัว (DM)

# 13. เกณฑ์ให้คะแนน (Impact Score)

ใช้ประเมินงานในโปรเจกต์ตามข้อเสนอ ARWEEN  
คะแนน 0–10 ตาม**ผลกระทบต่อ Milestone / KPI** ไม่นับจำนวนคำ  
High Impact Action = งานที่มีผลต่อเป้าหมายและตัวชี้วัดโครงการสูง  
บันทึกงานรายวัน = หลักฐาน (Evidence) ไม่ใช่ตัวตั้งคะแนนโดยตรง

## เกณฑ์หลัก

| คะแนน | ความหมาย | ตัวอย่างลักษณะงาน |
|-------|----------|-------------------|
| 0–2 | ตอบรับทั่วไป ไม่ช่วยงาน หรือไม่ผูกกับ KPI | "รับทราบ", "ขอบคุณ" |
| 3–4 | งานทั่วไป / อัปเดตสถานะ มีหลักฐานแต่ผลต่อตัวชี้วัดจำกัด | อัปเดตสั้น ๆ ไม่ปลดล็อกเป้าหมาย |
| 5–6 | ช่วยงานระดับปานกลาง ผูกกับ Milestone ได้ชัด | แก้เล็กน้อย มีประโยชน์ต่อแผน |
| 7–8 | High Impact ระดับโปรเจกต์ | แก้ปัญหาที่มีผลต่อความคืบหน้า Milestone |
| 9–10 | ปลดล็อก Blocker สำคัญของ KPI หลัก / High Impact สูง | แก้คอขวด Critical Blocker หรือมีผลต่อความสำเร็จโปรเจกต์สูงมาก |

ตาม Agent 1: งานทั่วไปมักได้ **0–3**; ช่วยปลดล็อก Blocker ของ KPI หลักได้ **8–10** พร้อมเหตุผล

## ตัวอย่างประมาณ 10 กรณี

### คะแนนต่ำ (0–2)

1. **"รับทราบครับ"** — ตอบรับเฉย ๆ → **1 คะแนน**
2. **"ขอบคุณค่ะ"** — ขอบคุณอย่างเดียว → **0 คะแนน**
3. **"โอเค"** — ยืนยันสั้น ๆ → **1 คะแนน**

### คะแนนกลาง (3–6)

4. **"อัปเดตแล้วครับ รอ review"** — แจ้งสถานะ → **4 คะแนน**
5. **"ช่วยเช็คไฟล์ config ให้หน่อยได้ไหม"** — ถามคำถาม ยังไม่แก้เอง → **3 คะแนน**
6. **"แก้ typo ในเอกสารแล้ว"** — ช่วยงานเล็กน้อย ผูก Milestone ได้บางส่วน → **5 คะแนน**

### High Impact (7–10)

7. **อธิบายวิธีแก้ bug ที่ทีมติดมา 3 วัน พร้อมขั้นตอน** (ปลดล็อก Blocker ของ KPI) → **9 คะแนน**
8. **ช่วยทีมดีไซน์แก้ layout ที่ทำให้หน้าเว็บพังบนมือถือ** → **8 คะแนน**
9. **รวบรวมข้อมูลจาก 3 แผนก แล้วสรุปให้หัวหน้าตัดสินใจ** (งานเบื้องหลังที่ขับเคลื่อน Milestone) → **9 คะแนน**
10. **"รับทราบครับ" ซ้ำหลายครั้งในวันเดียว** — สัญญาณปั่นคะแนน → **0 คะแนน + ธงตรวจสอบ (Agent 3)**

## งานเบื้องหลัง vs งานที่คนเห็นง่าย

ข้อเสนอเน้นแก้ปัญหา "ปิดทองหลังพระ"

- งานที่คนเห็นง่าย: นำเสนอในที่ประชุม พูดในห้องใหญ่
- งานเบื้องหลัง: ช่วยแก้ปัญหาให้เพื่อน ประสานงาน รวบรวมข้อมูลให้ทีม

**เกณฑ์เดียวกัน:** ให้คะแนนตามผลกระทบต่อ Milestone / KPI ไม่ใช่ตามว่าคนอื่นเห็นหรือไม่

## จาก Impact Score ไปสัดส่วน 100%

Agent 2 (Contribution Calculator) รวบรวม Impact Score ของทุกคนที่ผูกกับตัวชี้วัดในรอบนั้น  
แล้วแปลงเป็น **Contribution Ratio รวมกันครบ 100%** เพื่อใช้ประกอบ Merit-to-Earn  
(หัวหน้ายืนยันก่อนใช้จริง)

## ข้อความที่ไม่ช่วยงาน / สัญญาณผิดปกติ

- ข้อความซ้ำ ๆ ไม่มีเนื้อหาและไม่มีผลต่อตัวชี้วัด
- ชมกันเองเป็นวงโดยไม่มีงานจริง
- พิมพ์ยาวแต่ไม่มีข้อมูลใหม่

กรณีเหล่านี้ให้คะแนนต่ำ และอาจตั้งธงสัญญาณปั่นคะแนน (Agent 3 — Anti-Gaming Policy)

# 14. ข้อกำหนดเชิญสมาชิก

ARWEEN ไม่เปิดให้สมัครบัญชีเอง พนักงานเข้าทีมได้เฉพาะลิงก์เชิญจากหัวหน้าโปรเจกต์หรือผู้ดูแลระบบ

## โฟลว์หลัก

1. หัวหน้าสร้างโปรเจกต์ (หรือใช้โปรเจกต์ที่มีอยู่)
2. หัวหน้ากรอกอีเมลพนักงาน แล้วสร้างลิงก์เชิญ
3. พนักงานเปิดลิงก์ `/invite/[token]`
4. พนักงานเข้าด้วยบัญชี Google องค์กร
5. ระบบตรวจว่าอีเมลตรงกับคำเชิญ แล้วเพิ่มเป็นสมาชิกโปรเจกต์

## กฎ

| กฎ | รายละเอียด |
|----|------------|
| ห้ามสมัครสาธารณะ | หน้า `/register` ส่งไปหน้าเข้าสู่ระบบพร้อมข้อความว่าต้องมีลิงก์เชิญ |
| อีเมลต้องตรง | อีเมลจาก Google ต้องตรงกับอีเมลในคำเชิญ (ไม่สนตัวพิมพ์เล็กใหญ่) |
| ใช้ครั้งเดียว | ลิงก์ที่ใช้รับแล้วใช้ซ้ำไม่ได้ |
| หมดอายุ | ลิงก์ใช้ได้ 7 วันนับจากวันที่สร้าง |
| ผู้สร้างลิงก์ | เฉพาะหัวหน้าโปรเจกต์ (`lead`) หรือผู้ใช้บทบาท `LEAD` / `ADMIN` |

## การเข้าสู่ระบบ

- **บัญชีที่มีรหัสผ่าน** (เช่น บัญชีสาธิตแอดมิน): เข้าที่ `/login` ด้วยอีเมลและรหัสผ่าน
- **สมาชิกใหม่**: ต้องมีลิงก์เชิญ แล้วเข้าด้วย Google Workspace
- **บัญชี Google ที่มีอยู่แล้วในระบบ**: เข้าที่ `/login` ด้วยปุ่ม Google ได้ โดยไม่สร้างโปรเจกต์เอง

## Data Privacy

- ประมวลผลเฉพาะพื้นที่โปรเจกต์ส่วนรวม
- ไม่เข้าถึงหรือวิเคราะห์ข้อความส่วนตัว (Direct Messages)
- ใช้คะแนนประกอบการตัดสินของหัวหน้า ไม่จ่ายเงินอัตโนมัติใน MVP

3. ล็อกสัดส่วนผลงานรายบุคคลรวม 100% ในเกณฑ์ผลิตภัณฑ์ — ลงโค้ดและข้อมูลจริงเป็นขั้นถัดไป
4. หัวหน้ายังเป็นผู้ตัดสินสุดท้าย ตามหลัก Audit Trail และ Dispute

# 17. สิ่งที่ทำแล้ว และสิ่งที่เลื่อน

## ทำแล้ว (เวอร์ชันต้นแบบที่เปิดใช้จริง)

- เข้าสู่ระบบด้วย Google หรืออีเมล (Firebase Auth)
- พื้นที่โปรเจกต์ส่วนรวม และบันทึกงานรายวัน
- ผู้ช่วย AI ให้คะแนน 0–10 พร้อมเหตุผล และแชทในบริบทโปรเจกต์
- หน้าสรุปความคืบหน้าและคะแนนสะสม
- สรุปภาพรวมทีมจากบันทึกงาน
- ลิงก์เอกสาร Google ในโปรเจกต์
- Deploy บน Cloud Run
- กฎไม่แตะข้อความส่วนตัว
- ล็อกเกณฑ์เปอร์เซ็นต์ 2 มิติในเอกสารผลิตภัณฑ์

## ทำบางส่วน

- ประวัติคะแนนที่ย้อนดูได้
- การโต้แย้งคะแนน (เอกสารและโครง Prisma)
- การเชิญสมาชิกองค์กร (ยังไม่ต่อกับ Firebase login)
- ความคืบหน้า % — ยังไม่ผูกน้ำหนัก Milestone / KPI ครบ
- สัดส่วนรายบุคคลรวม 100% — ล็อกในเอกสารแล้ว รอลงโค้ด

## เลื่อนไว้รอบถัดไป

- จ่ายโบนัสหรือเชื่อมระบบเงินเดือนอัตโนมัติ
- พื้นที่พิมพ์งานแบบบล็อกคล้าย Notion ทั้งระบบ
- ติดตั้งบนคลาวด์ส่วนตัวของลูกค้า
- บัญชีองค์กร Microsoft 365
- เหรียญรางวัลดิจิทัล / บล็อกเชน

หลักการเวอร์ชันต้นแบบ: **ทำให้คะแนนและสัดส่วนโปร่งใส ตรวจสอบได้ และผูกกับเป้าหมายโครงการก่อน แล้วค่อยเชื่อมผลตอบแทน**

# สรุปสั้นหนึ่งย่อหน้า

ARWEEN คือระบบช่วยให้งานในโปรเจกต์ถูกบันทึกและประเมินอย่างโปร่งใส โดยยึดวัตถุประสงค์ เป้าหมายงานส่งมอบ และตัวชี้วัดเป็นตัวตั้ง ให้ผู้ช่วยปัญญาประดิษฐ์ทำงานเบื้องหลัง ให้คะแนนผลกระทบพร้อมเหตุผล คำนวณความคืบหน้าโครงการและสัดส่วนผลงานรายบุคคล เพื่อให้งานเบื้องหลังถูกมองเห็น และในอนาคตนำไปสู่ผลตอบแทนที่เป็นธรรม โดยหัวหน้ายังเป็นผู้ตัดสิน ไม่ใช่ระบบจ่ายเงินเองในเวอร์ชันต้นแบบ
