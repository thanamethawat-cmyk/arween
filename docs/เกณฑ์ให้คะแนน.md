# เกณฑ์ให้คะแนน

ใช้ประเมินงานในโปรเจกต์ คะแนน 0–10 ตามผลกระทบต่องาน ไม่นับจำนวนคำ

---

## เกณฑ์หลัก

| คะแนน | ความหมาย |
|-------|----------|
| 0–2 | ตอบรับทั่วไป ไม่ช่วยงาน (เช่น "รับทราบ", "ขอบคุณ") |
| 3–4 | แจ้งสถานะหรือถามคำถามง่าย ไม่แก้ปัญหา |
| 5–6 | ช่วยงานระดับปานกลาง มีประโยชน์แต่ไม่ซับซ้อน |
| 7–8 | แก้ปัญหาที่มีผลต่อโปรเจกต์ อธิบายชัดเจน |
| 9–10 | แก้ปัญหาซับซ้อน ช่วยทีมข้ามสายงาน มีผลต่อความสำเร็จของโปรเจกต์ |

---

## ตัวอย่าง (ประมาณ 10 กรณี)

### คะแนนต่ำ (0–2)

1. **"รับทราบครับ"** — ตอบรับเฉย ๆ ไม่มีการทำงานเพิ่ม → **1 คะแนน**
2. **"ขอบคุณค่ะ"** — ขอบคุณอย่างเดียว → **0 คะแนน**
3. **"โอเค"** — ยืนยันสั้น ๆ ไม่มีรายละเอียด → **1 คะแนน**

### คะแนนกลาง (3–6)

4. **"อัปเดตแล้วครับ รอ review"** — แจ้งสถานะ มีประโยชน์เล็กน้อย → **4 คะแนน**
5. **"ช่วยเช็คไฟล์ config ให้หน่อยได้ไหม"** — ถามคำถาม ยังไม่แก้เอง → **3 คะแนน**
6. **"แก้ typo ในเอกสารแล้ว"** — ช่วยงานเล็กน้อย → **5 คะแนน**

### คะแนนสูง (7–10)

7. **อธิบายวิธีแก้ bug ที่ทีมติดมา 3 วัน พร้อมขั้นตอน** — แก้ปัญหาซับซ้อน มีผลต่อโปรเจกต์ → **9 คะแนน**
8. **ช่วยทีมดีไซน์แก้ layout ที่ทำให้หน้าเว็บพังบนมือถือ** — ช่วยข้ามสายงาน → **8 คะแนน**
9. **รวบรวมข้อมูลจาก 3 แผนก แล้วสรุปให้หัวหน้าโปรเจกต์ตัดสินใจ** — งานเบื้องหลังที่มีผลสูง → **9 คะแนน**
10. **"รับทราบครับ รับทราบครับ รับทราบครับ" ซ้ำหลายครั้งในวันเดียว** — ข้อความซ้ำไม่มีประโยชน์ (สัญญาณปั่นคะแนน) → **0 คะแนน + ธงตรวจสอบ**

---

## งานเบื้องหลัง vs งานที่คนเห็นง่าย

- งานที่คนเห็นง่าย: นำเสนอในที่ประชุม พูดในห้องใหญ่
- งานเบื้องหลัง: ช่วยแก้ปัญหาให้เพื่อน ประสานงานหลังบ้าน รวบรวมข้อมูลให้ทีม

**เกณฑ์เดียวกัน:** ให้คะแนนตามผลกระทบต่องาน ไม่ใช่ตามว่าคนอื่นเห็นหรือไม่

---

## ข้อความที่ไม่ช่วยงาน

- ข้อความซ้ำ ๆ ไม่มีเนื้อหา
- ชมกันเองเป็นวงโดยไม่มีงานจริง
- พิมพ์ยาวแต่ไม่มีข้อมูลใหม่

กรณีเหล่านี้ให้คะแนนต่ำ และอาจตั้งธงสัญญาณปั่นคะแนน
